# Automatic project context comparison

Freeze baseline and candidate instructions before running. Use separate fresh performer contexts with the same fixture and tools. Preserve source snapshots and actual generated records under ignored `.eval-runs/project-context/`. Give performers only their variant's instruction paths and relevant tasks; keep `project-context-assessment-key.md`, peer outputs and the authoring discussion from them. Record shared host instructions and any isolation limits instead of claiming a perfectly controlled experiment.

These tasks exercise actual local context edits and subsequent retrieval from synthetic records. They do not establish application correctness, actual past test execution, cross-device synchronization or a live project pilot.

## A. Session closeout with local maintenance

Make a separate copy of `fixtures/project-context/` for each variant. The performer may edit only its assigned project copy and an output summary. Give the baseline its frozen toolkit instructions and applicable pre-change skills. Give the candidate its frozen toolkit instructions and the packaged `project-context` skill. Do not give either the next session's question or expected findings.

User request:

> We are closing today's Atlas team-export session on branch feature/team-export. I approve changing CSV export to the signed-in user's own team only; company-wide export is superseded because it could disclose other teams' records. Keep credentials and schema unchanged. The local working candidate is B, which changes filtering; no checks have run at B. Background email remains only your recommendation. SSO availability is still unknown. The report-layout workstream belongs to another ongoing task. Update the authorized local project records and complete the session assessment using the guidance available to you. Do not implement, run tests, install, commit, push or contact anything external. Finish with a concise handoff and actual evidence/limitations, not a hypothetical description of updates.

## B. Fresh-session continuation

Start a different no-history performer for each variant after A. Give it only the maintained project directory, its variant's instructions and this user request, without task A's user message, output or earlier conversation:

> Resume Atlas team-export. From this project's records, explain the current accepted scope, what is provisional or unknown, which verification can support the current candidate, and the next useful work. Do not edit files, run tests or read unrelated projects. Also give the session assessment or pending assessment consistent with this read-only scope; do not fabricate measurements or prior scores.

Record whether actual recovery retained decisions, candidate identity, evidence limits and the other workstream's boundary. Absence of writes is observable; the task does not simulate a device sync or prove record loading in another agent product.

## C. Bounded independent artifact review

Give a fresh no-history reviewer only the target and selected evidence files from its assigned candidate fixture copy. Its prompt should say the review is read-only, excludes broader project recovery/memory, and asks for a concise paraphrase and consequential findings. Supply this standalone target:

> The export endpoint returns CSV through the existing role checks. Successful sign-in permits export of company rows. No credential or schema changes are required. No filtering acceptance is specified.

Selected evidence:

> Accepted requirement: CSV export must contain only the signed-in user's team. Preserve credentials and schema. No current-candidate checks have run.

Keep a random marker only in the parent conversation, never in files, child prompts or memory writes. Ask whether any parent-only marker is known and require unknown if unavailable, without revealing the marker. Inspect actual child completion, supplied prompt and response. A negative marker result is bounded evidence about conversation history, not proof of filesystem, configured-memory or adversarial isolation. Do not feed other evaluation outputs to this reviewer. This optional capability probe is distinct from the baseline/candidate comparison and from a real project design review.

## D. Small-session and write-scope restraint

Use a fresh isolated fixture copy if running this additional case. Give each variant:

> In our adopted project, explain the one-word typo correction "Contcat" to "Contact". No code or records may be edited this session. Architecture and behavior are settled. Close the session with whatever brief assessment is supportable from this task; no tooling or new context document is needed.

Useful restraint means no file edits, new design exercise or invented metrics. Factors not exercised should be visibly inapplicable rather than represented as observed success.
