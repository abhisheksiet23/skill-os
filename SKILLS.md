# Skill catalog

This is a human review aid, not a routing database. Each skill's description is the native discovery surface. Recommendations are optional; no row requires another row.

| Skill | Main job | Boundary |
| --- | --- | --- |
| [project-context](skillmesh/skills/project-context/SKILL.md) | Automatic project-owned context, continuation and session assessment | Adopted projects and handoffs; no global memory store or mandatory skill chain |
| [project-manage](skillmesh/skills/project-manage/SKILL.md) | Outcome control, next-path planning, schedule/AI-tool-spend forecasts and corrective decisions | Tailored AI-led delivery or standalone project review; no simulated roles, routine approval loop or mandatory artifacts |
| [code-navigation](skillmesh/skills/code-navigation/SKILL.md) | Definitions, references, implementations and code impact with semantic tools and search | Explicit current-project binding, source verification and fallback; no required provider or semantic editing |
| [venture-investigate](skillmesh/skills/venture-investigate/SKILL.md) | Evidence-backed pursue, reshape, park or reject decision | Broad investigation; focused questions need less expertise |
| [market-research](skillmesh/skills/market-research/SKILL.md) | Competitors, substitutes, buyer/market evidence and value curves | Advertised offers do not prove purchases or profitability |
| [business-validate](skillmesh/skills/business-validate/SKILL.md) | Falsifiable, cheap customer/demand tests | Learning, not implied outreach or implementation |
| [business-pricing](skillmesh/skills/business-pricing/SKILL.md) | Payer, metric, package and price hypotheses | Provisional prices are not validated willingness to pay |
| [business-model](skillmesh/skills/business-model/SKILL.md) | Delivery, capacity, economics, cash and growth | Scenarios are conditional, not demand proof |
| [business-challenge](skillmesh/skills/business-challenge/SKILL.md) | Skeptical evidence and assumption review | Specific contradictions, not automatic negativity |
| [naming-architect](skillmesh/skills/naming-architect/SKILL.md) | Naming strategy, candidate critique and recommendations | Proportionate research and preliminary screening; no invented availability or legal clearance |
| [website](skillmesh/skills/website/SKILL.md) | Whole-site coherence for broad marketing-site work | Judgment, not routing or mandatory child skills |
| [website-discover](skillmesh/skills/website-discover/SKILL.md) | Buyer, offer, positioning and claims | Website strategy, not a full venture case |
| [website-create](skillmesh/skills/website-create/SKILL.md) | Copy, art direction and responsive prototype | Non-production experience, not live delivery |
| [website-build](skillmesh/skills/website-build/SKILL.md) | Production marketing site and integrations | Existing direction accepted; no implied publishing |
| [website-review](skillmesh/skills/website-review/SKILL.md) | Buyer clarity, craft and conversion verification | Standalone audits need no discovery records |
| [website-deliver](skillmesh/skills/website-deliver/SKILL.md) | Authorized launch and owner handoff | Live proof and business results remain distinct |
| [app-analyze](skillmesh/skills/app-analyze/SKILL.md) | Requirements analysis/review, existing behavior and behavioral contracts | Analysis, not technical architecture review, production code or demand proof |
| [app-solution-design](skillmesh/skills/app-solution-design/SKILL.md) | Technical design/plan authoring and review, architecture trade-offs and cross-component guarantees | Standalone review or unresolved technical approach; no mandatory phase |
| [app-prototype](skillmesh/skills/app-prototype/SKILL.md) | Inspectable application experience and states | Material UX; contained fixes use existing baseline |
| [app-frontend](skillmesh/skills/app-frontend/SKILL.md) | Application UI implementation and integration | Real API when present; mocks only where useful |
| [app-backend](skillmesh/skills/app-backend/SKILL.md) | Domain, API, data, migrations and integration | No frontend-first prerequisite |
| [app-qa](skillmesh/skills/app-qa/SKILL.md) | Behavior and engineering verification | Standalone/review-only supported |
| [app-deliver](skillmesh/skills/app-deliver/SKILL.md) | Authorized software release and knowledge | Preparation and verified delivery are distinct |

Website expertise emphasizes marketing narrative and conversion; app expertise emphasizes workflows and domain behavior. An application-backed marketing journey may benefit from both for actual gaps. Business validation establishes demand evidence; website discovery establishes a credible site story. Neither automatically reruns the other.

The agent owns orchestration, guided by `AGENTS.md`. Tools/connectors such as TWG, Sites, documents and image generation remain separate capabilities; this library does not duplicate or remove them.
