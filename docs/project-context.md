# Project-owned context policy

| Policy | Current rule |
| --- | --- |
| Authority | Accepted owner decisions stay distinct from recommendations, assumptions and source-bound observations |
| Location | Context and assessments stay in their owning project; use adequate existing records |
| Retrieval | Recover project/workstream identity and relevant current sources; deepen only for consequential gaps |
| Maintenance | Update changed facts and current continuation state, preserving unrelated work and superseded decision rationale |
| Closeout | Keep a compact checkpoint and honest assessment; a work period is not each reply |
| Boundaries | Local upkeep does not authorize commits, pushes, installations, deployment or external writes |
| Review | Fresh reviewers receive the target and selected evidence, excluding author narratives and session assessments |

Use [project-context](../skillmesh/skills/project-context/SKILL.md), its [portable instruction example](../skillmesh/skills/project-context/assets/project-instructions.md) and [rubric](../skillmesh/skills/project-context/references/session-assessment.md) when applicable. Adapt paths and verify instruction loading; installation alone does not establish activation or continuity.

For this toolkit's clean state, retain the current checkpoint and latest assessment only. Do not carry old scores, run conclusions or installation claims forward. Explicit owner resets override historical retention; accepted policy and attribution remain. Other projects keep their own authorized retention rules. No current real-project efficiency, cross-device reliability or provider-savings claim is established.
