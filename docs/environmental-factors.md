# Environmental factors

As of 2026-11-23. These factors apply when authoring, deploying or evaluating SkillMesh. They describe requirements and known constraints, not a current device-health check. Verify device-specific conditions in the active environment. Keep installation evidence and recovery paths in the ignored `docs/installation-status.local.md`.

| Factor | Constraint or opportunity | Practical consequence | Verify when |
| --- | --- | --- | --- |
| Shared source and local discovery | GitHub carries the authoring source. Windows installs and cloud checkout links use distinct discovery paths. Cloud repository access supplies neither local credentials nor installed tools. [Cross-device and cloud setup](github-and-cloud.md) | Refresh via the target's supported setup. Use checkout links in cloud and avoid duplicate local discovery. | Changing devices, host or discovery path. |
| Deployment and caches | The Windows installer rebuilds a deployment copy, updates its version marker and reinstalls. Existing chats can retain their captured catalog. [Migration](migration.md) | Change the authoring source, rebuild via the installer when authorized and inspect discovery in a new chat. Keep recovery details local. | After changing packaged source or recovering an installation. |
| Host tools and models | Native catalog, plugin support, connectors, model choices and spending authority depend on the active session and account. The package supplies a Serena configuration using native stdio. [Serena package and startup](serena.md#package-and-startup) | Inspect available capabilities at use time. Verify root binding with a known lookup. Use direct search for unsupported or unavailable paths. Use economical delegation only where available and authorized, with adequate verification. | Starting a new host/session, switching roots or choosing a model or provider for consequential work. |
| Dependencies and permissions | Serena can need first-use network downloads and writable caches. Angular template lookup depends on the application's packages. The bundled Roslyn backend has its own SDK prerequisites. Windows script policy and junction creation can constrain migration verification. [Serena dependencies](serena.md#installation-and-dependencies), [junction fixture](../scripts/Test-Migration.ps1) | Confirm dependencies and authorized access before a live check. Prewarm supported backends during authorized setup. Report any portion blocked by network, write, link or script restrictions and use available checks within scope. | First setup, backend/version changes or a permission-sensitive test. |
| Measurement | The metadata-only runner records selected operations in the owning project. Separate provider usage, token counts, attributable cost and savings require separate evidence. [Tracking limits](use-tracking.md#records-and-limits) | Distinguish observations and estimates. Record missing measurements as unknown and preserve rework and partial coverage. | Claiming effort, savings or performance, or changing how operations are collected. |
| Evidence ownership | Application facts, decisions and acceptance evidence belong to the application project. Synthetic integration checks cover the documented package paths. [Project context](project-context.md), [Serena verification](serena.md#verification-and-recovery) | Use the actual project's candidate, dependency state and authorized target for application claims. Bring only authorized sanitized lessons back to the toolkit. | Reusing evidence after a candidate, environment or scope change. |
