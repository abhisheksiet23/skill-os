# Project Context

Make the next session able to continue the right work without rediscovering decisions or trusting stale evidence. Maintain authoritative project knowledge within existing authorization. Success is accurate recovery and useful continuation; producing more records does not establish it.

The agent owns maintenance and synthesis; this skill never invokes another skill. Facts, decisions and assessments belong in the project, while reusable lessons belong in skills. Use adequate existing records without requiring a database, memory service, fixed folder tree or earlier invocation.

## Recover the current workstream

Establish the project root/identity and current task, branch or workstream. Read its small instruction map and relevant current records, then retrieve focused sections as needed. Accept existing requirements, decisions, issues and continuation notes. Use relative links within the project; machine-specific absolute paths and another project's defaults are not portable facts. Native memory is a lead to verify against current project evidence, not authority over it.

For an adopted project, follow its existing map and update responsibilities. When adoption itself is in scope, extend those records with any missing authoritative sources, workstreams and assessment destination. Adapt [the portable instruction snippet](assets/project-instructions.md); its example paths are not required structure. Verify that the intended agent loads the guidance. Installation or file presence alone does not prove activation. Leave global instructions and unrelated projects alone.

## Preserve intent and evidence at their sources

Record explicit owner decisions as accepted, observations as verified only within their source/revision/environment, and recommendations or assumptions as provisional. Supersede replaced decisions with the replacement and reason; do not erase their rationale. If implementation contradicts accepted intent, record the discrepancy rather than silently rewriting the requirement to match the code. Preserve unknowns and accepted trade-offs.

Update the authoritative record after consequential changes and before closeout or handoff. Link detailed evidence rather than copying transcripts, command logs or the same decision into multiple summaries. Keep the map small and remove obsolete duplication. Markdown suits explanatory context; use small structured metadata only when it aids retrieval. Existing search is the default. Introduce indexes only for measured retrieval problems, keeping them rebuildable from project sources.

Leave enough continuation state to recover the objective, current boundary, candidate and relevant uncommitted changes, checks with their limits, open decisions, and next useful action or stopping reason. Keep it scoped to the workstream and link supporting evidence.

Re-read the destination before editing and preserve unrelated changes. This reduces overwrite risk but is not an atomic concurrency guarantee: reconcile conflicting evidence and accepted authority before replacing the same fact. Newest timestamp alone does not settle a conflict. Keep past passes attached to their tested candidates. Local upkeep does not authorize commits, pushes, external edits or publication; expose unsynced state when another device needs it.

When ongoing project control is adopted, map its authoritative outcome, current position, next milestone/path and forecast/cost sources. Ordinary implementation that completes/invalidates a milestone or changes its driving blocker triggers a bounded update without waiting for a status request. At resumption reconcile summary claims with current evidence; preserve as-of limits and unknowns. Continuity maintenance does not invent estimates, acceptance or billing data, duplicate management calculations, or require a management exercise for every correction or context-only handoff. The project's existing delegation and control responsibilities remain authoritative.

## Leave a usable checkpoint and an honest assessment

At completion of a coherent project work period, explicit pause or handoff, update continuation context and fill a concise session assessment using [the assessment rubric](references/session-assessment.md). This is an adopted project obligation, including sessions with no code changes; it is not a report for every conversational reply. Reuse the project's mapped assessment record; when none is mapped and this task already has a work report, place the assessment there, keeping self-assessment scores out of the owner-facing current project view. Do not create a second report solely for assessment. The [compact example](assets/session-assessment.md) is optional. Routine work can need one row with N/A factors. Do not block useful work on missing historical scores.

Creating or rereading a checkpoint does not establish successful continuity. In a maintenance-only closeout, mark that factor unknown until a separate resumption or recipient actually recovers the maintained state.

If the session ends abruptly, no background closeout is promised. On resumption, reconcile changed evidence and record the missed assessment as a gap; never reconstruct an unobserved pass. Explicit no-write instructions override housekeeping: give a proposed update or pending assessment in the response instead. Routine authorized maintenance needs no repeated approval. Keep project assessments local to that project; only sanitized, generalized lessons belong in the toolkit and only when its source is available and edits are authorized. Do not invent token/cost savings or treat a self-assessment as independent proof.

## Keep fresh review independent of the authoring narrative

For a fresh review, supply only the target, selected source evidence and legitimate constraints. Exclude authoring transcripts, speculative working notes, desired answers and unrelated project/session assessments. Use the native tool's no-history option when available and authorized; do not claim isolation from a same-context reread. Shared filesystem and project instructions remain accessible unless separately restricted. Do not retrieve prior chat or memory to fill artifact gaps. Record actual reviewer completion and limitations; missing evidence or a failed reviewer is incomplete review. Keep assessment notes out of automatic reviewer bootstrap and assess isolation only when exercised.

Finish when the relevant sources and checkpoint agree, consequential unknowns remain visible, and the required assessment is recorded or explicitly pending under a no-write constraint. Return the current position and next useful action. Future recovery remains unproved until observed.
