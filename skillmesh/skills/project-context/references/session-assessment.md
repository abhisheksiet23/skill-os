# Project session assessment

Use the assessment to find failures in continuity and upkeep that should change future work. Assess the coherent work period actually observed, including analysis-only and small-change sessions when the project has adopted this obligation. Identify date, workstream, relevant candidate/environment, outcome, evidence and next action in its existing record. A short entry or row is sufficient when it preserves those distinctions. Keep concurrent workstreams separate and explain later corrections through changed evidence.

## Score observations, not intentions

Score each factor **0** for an observed failure, **1** for partial success or a material gap, **2** for evidenced success. Use **unknown** when the factor could apply but was not observed, and **N/A** with a reason when not exercised. Do not average away a consequential failure or turn unknown/N/A into zero or a pass. Self-assessment is labeled as such; user feedback and independent checks remain distinct.

In a maintenance-only closeout, continuity is **unknown** until a separate resumption or recipient actually recovers the maintained state. Writing or rereading the checkpoint and reconstructing the fixture's prior input are not that observation. In an actual resumed session, identify the records and decisions recovered; scope the score to that recovery, not the next unobserved handoff.

## Check the six factors

| Factor | What earns evidenced success | Failure to look for |
| --- | --- | --- |
| Continuity | Resumption or handoff recovered the correct goal, constraints, open questions and next action from project records | Repeated discovery or lost constraints; a checkpoint's existence alone does not prove recovery |
| Decision fidelity | Material accepted decisions, provisional assumptions and superseded choices remain distinguishable with provenance | Agent preference promoted to approval; unsupported facts or deleted rationale |
| Evidence freshness | Important claims/checks identify the candidate/environment and stale or unavailable proof remains explicit | Old tests applied to new code; documented limitations mistaken for proof |
| Retrieval economy | Observed reads were scoped to the task, avoided duplicate/broad loading and still recovered necessary evidence | Excessive context or omitted consequential evidence; brevity alone earns no credit |
| Project/workstream separation | Actual updates preserved the right project identity, branch/task state and unrelated records | Foreign defaults, overwritten concurrent state or unscoped retrieval |
| Review independence | A completed reviewer used verified no-history dispatch and the selected evidence; known limits are recorded | Authoring history or answers supplied; a timeout/reread called independent review |

For review independence, score 2 only for the observed conversation/evidence boundary, never as proof of filesystem or memory isolation. If no independent review was attempted, use N/A. A fresh reviewer returning zero findings is not itself an isolation test.

## Explain measurements and use the result

Record provider tokens, elapsed time, reads/tool calls and user corrections only when observed, with their measurement boundaries; otherwise mark them unknown. Word count is not token usage. A shorter read that misses an important constraint is not economical. Savings require comparable work and equivalent outcomes, so describe retrieval observations without inventing a percentage. Link essential evidence and retain raw logs only when they substantiate a claim that cannot otherwise be checked.

Finish with the smallest useful correction or the next observation needed. Accumulate real project-session evidence before changing toolkit defaults or adding retrieval infrastructure. Repeated failures may justify a narrow instruction or tooling change; individual project facts and private evidence stay in the project. A toolkit pilot note can track sanitized lessons when updating that repository is authorized. Assessment does not authorize deploying, contacting others, syncing remote records or retrospectively changing user decisions.
