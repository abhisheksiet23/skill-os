# Code Navigation

Answer the current code question using the smallest useful source slice. Available semantic tools can reduce ambiguous text matches; their presence does not establish complete coverage or replace source verification. Work with existing tools when Serena is unavailable.

Establish the active repository/worktree root from the task, not the plugin path. Before Serena activation, inspect existing `.serena/project.yml` and `project.local.yml` when present for activation commands, language settings and ignored paths. Follow project instructions and task authorization; do not execute an unexpected activation command merely to enable navigation. Activation may create provider configuration/caches in a writable project. Respect review-only/no-write scope: use search if activation would write outside the allowed boundary.

Read Serena's initial instructions when exposed, pass its supplied session ID when activating the absolute project root, and confirm the root with `get_current_config`. For each language relevant to the change, validate a known definition and, when the question depends on relationships, a known caller/reference before relying on semantic coverage. One working language does not establish another's readiness; do not probe unrelated languages or repeat valid checks for an unchanged binding/configuration. Activation may return before language-server initialization finishes. Warm a newly installed backend before simultaneous cold activations, which can collide while extracting shared dependencies. Use overviews to locate symbols, fetch relevant bodies, then references/implementations to trace impact. Scope queries by file or subtree where practical. Recheck the root after a project switch; do not share a mutable active-project server between unrelated sessions. Serena's reported line numbers are zero-based; verify/convert them for one-based source citations.

Distinguish configured languages from those loaded by the active provider process. After a project-local configuration repair, verify the affected lookup in the active process; a saved file or successful reactivation alone is not proof that settings reloaded. If it retains old settings, use the host-supported refresh or a fresh task-owned provider process within authorization, then recheck binding and the affected definition/relationship. Do not terminate another chat's provider. Dependency installation or application framework changes need their own task authorization; navigation readiness does not supply it. If refresh or repair is unavailable or outside scope, continue with source search and report the specific semantic gap.

An empty response is not proof of no usages. Check initialization, language support, dependencies and ignore rules. Use `rg` and file reads for unsupported paths, routes, configuration, reflection, SQL and framework relationships. For Angular, verify template relationships separately; the language server needs resolvable Angular dependencies. For C#, verify backend/runtime compatibility without changing the application's target framework.

Keep application facts and navigation findings in the owning project. This bundle exposes navigation, not Serena editing, shell execution or memory management. Continue the authorized task through ordinary tools; tool failure must not block useful work. Report consequential coverage gaps and count fallback/correction effort before claiming savings.
