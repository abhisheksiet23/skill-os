# Microcopy craft

Start with the user's task, the actual system state, what is known, and the actions available. Copy must preserve validation rules, scope, consequences and uncertainty. A shorter message that changes the behavior's meaning is a regression. Do not infer a cause from a generic failure or promise data safety, payment status, recovery time or progress without supporting behavior or evidence.

## Choose the pattern from the state

| Situation | Useful content | Distinction to preserve |
| --- | --- | --- |
| Field validation | Requirement and how to meet it, next to the field | Match the actual rule; an email containing @ is not necessarily valid |
| Recoverable failure | What failed, known context, supported next action | Retry only when appropriate; an unknown payment outcome needs status checking before another payment |
| Blocking failure | What is unavailable and the available alternative or next step | Give a restoration estimate or reassurance only when established |
| Success | What completed and any consequential next step | Accepted, queued, sent and delivered are different states |
| First-use empty state | What belongs here and a useful starting action | Offer creation only when the user can create |
| Completed work | What is complete and when more work appears, if known | An empty list alone does not establish completion |
| No results | Which search or filters found no matches and how to adjust them | Do not imply that the underlying collection is empty |
| Restricted access | What the user can know and how access can be obtained | Do not expose protected content or disguise access restrictions as no results |
| Permission request | Specific benefit, permission needed, and available choice | Explain in context; distinguish optional permission from a prerequisite and preserve platform-owned wording |
| Destructive confirmation | Affected object, scope, consequences, reversibility and explicit action | Preserve retention exceptions and recovery windows; do not exaggerate permanence |

Treat these as prompts for judgment, not mandatory title/body/button formulas. Routine confirmation may need only a short completion message. An unavailable action does not need an invented CTA.

## Voice, tone and editing

Use the project's terminology, house style and product voice, especially representative approved strings. Examples illustrate choices; they do not prescribe wording or a universal voice. When consistency needs clarification, record project-specific contrasts. For a new voice, use known customer circumstances and company values where they resolve a writing choice; keep proposals provisional and surface conflicts. Do not manufacture a brand exercise for a contained correction.

Keep voice recognizable while adapting tone to the task: brief for routine completion, explanatory for first use, calm and practical for failure, explicit about consequences for high-stakes choices. Avoid forced celebration, blame, artificial urgency and guilt for declining. Conversational language need not be casual or less precise.

Review wording through four lenses: does it serve the task, can words be removed without losing meaning, does it sound natural for this audience, and is its meaning unambiguous? Preserve useful specialist vocabulary. Fixed sentence lengths, reading grades and active-voice percentages are not acceptance criteria; do not truncate essential instructions to meet them.

Write for scanning: lead with the meaningful state, outcome or action, and make labels understandable independently. If extensive explanation is needed to make a flow usable, reconsider the interaction.

## Content in the interface

Use visible field labels and descriptive actions and links. Read labels, helper text and errors together for repetition or missing context. Accessible names should preserve visible wording; add hidden context only where needed. Alternative text should convey an image's purpose without repeating adjacent content; decorative images need no redundant announcement. Good wording alone does not establish correct semantic association or announcement behavior.

Where localization is in scope, test realistic expanded labels, plural/count variants, dates and long values in the represented layouts. Avoid idioms and sentence fragments assembled from translated pieces. Use actual locale conventions and available translations rather than universal expansion percentages.

Inspect the copy in its actual state and layout. Record meaningful before/after wording, the rule or evidence preserved, and any unresolved factual dependency using existing project records. Editorial judgment can explain a revision; comprehension and task-success improvements require observed user evidence.
