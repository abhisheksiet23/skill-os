# Existing-system evidence

Bound the recovery by the requested outcome, actors and entry points.
- Defect: trace its affected path.
- Replacement: map it shallowly before investigating detail.
- Retained module or configurable widget: confirm it belongs to or materially constrains the increment before recovering all its behavior.

## Recover the baseline
- Inspect relevant source, runtime behavior, schema and records.
- Record source and environment identity; a commit alone does not identify a deployment.
- Find paths, symbols and exact database objects before retrieving contents. Narrow searches and truncated results; missing evidence is unknown, not absent.
- Confirm usable read-only tools once and reuse them.
- Trace consequential validation, permission and data scope, persistence, jobs, reports, history and external effects. One screen or role is not the system.
- Reuse unchanged evidence only while its code, deployment, data and question still apply.

## Handle secrets
- Use supported secret input or references for authenticated checks.
- Raw secrets must not enter recorded inputs, shell history, scripts or evidence; redaction cannot undo exposure.
- If secure input is unavailable, block that check and continue independent discovery. Keep private payloads out of durable records.

## Reconcile behavior and compatibility
- Separate observation, inference and target intent.
- Resolve conflicting code, records or runtime evidence by checking for dead code, stale documents or different deployments. Decide what is preserved, changed or retired.
- For an uncertain legacy contract, keep exact stored identifiers beside domain and transport labels, and name the early read-only check that establishes the real mapping. Mocks cannot prove it.
- For coexistence, establish entry routing, session and auth boundaries, authoritative writers, old and new contract compatibility, retained jobs and consumers, and cutover and recovery.
- Uncoordinated dual writes are not a migration strategy. Routing rollback does not undo new data: prove old code can read new writes, or define reconciliation or forward recovery.

Leave baseline evidence, material dependencies, target decisions, acceptance and exact gaps in adequate existing records. No discovery dossier or particular provider is required.
