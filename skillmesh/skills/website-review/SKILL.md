# Website Review

Identify the candidate URL/revision, environment, requested scope and success criteria. Use existing briefs when available; for an existing-site audit, state inferred purpose and limitations rather than requiring a discovery project first.

Inspect actual pages and important journeys. For a substantial review use [review guidance](references/review-guide.md). Evaluate story, fit, evidence, copy, imagery, hierarchy, responsive composition, accessibility, functionality and operating ownership together. Do not mistake attractive generic copy for a credible offer.

Render and examine representative narrow, intermediate and wide layouts at recorded sizes. Exercise navigation, CTA, keyboard/focus, form validation and failure recovery. Test external delivery only within authorization. Reuse trustworthy checks for the same candidate; a local build, screenshot and verified receipt establish different things.

Report each material issue with location/state, observation, buyer consequence, evidence and actionable correction. Group systemic issues. Fix reversible implementation defects only when in scope; review-only work reports findings without editing the site. Recheck affected views/journeys after fixes.

Missing tools, credentials or evidence leave the relevant check unverified. A fake primary conversion and unsupported central claims cannot become a pass because other checks succeed. Distinguish readiness, verification completeness and publication authority.

Save concise findings in the project's existing records and stop at the requested review outcome. Recommend `website-discover` for unresolved positioning, `website-create` for design problems, or `website-deliver` for an authorized launch need. The agent assesses these recommendations; this skill never invokes another skill or starts a mandatory workflow.
