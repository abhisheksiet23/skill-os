# Website Review

Determine whether a concrete website lets its intended visitors understand the offer, trust its claims and complete a useful action. Return a candidate-bound judgment with actionable evidence, separating readiness from verification coverage and publication authority.

## Frame the review

Identify the URL/revision, environment, requested scope and success criteria. Use existing briefs; for an audit without one, state the inferred purpose and its limitations instead of requiring a discovery project. Respect review-only scope. Independent review benefits from the target and necessary raw evidence without being steered by the author's desired conclusion.

## Inspect the actual experience

For substantial review read [review guidance](references/review-guide.md). Sample representative page types and unusual states, covering all business-critical journeys. Assess story, fit, proof, copy, imagery, hierarchy, responsive composition, accessibility, functionality and operating ownership together. Attractive generic copy is not a credible offer.

Render and examine narrow, intermediate and wide layouts at recorded sizes. Exercise navigation, CTAs, keyboard/focus, form validation and recovery. Reuse trustworthy evidence for the same candidate, distinguishing build results, screenshots and actual receipt. External delivery tests require authorization; missing tools or credentials leave their checks unverified.

When implementation/source readability is in scope, inspect it for an owner returning after six years: blank lines between logical blocks and meaningful UI sections, cohesive groups, expanded guards/branches/error handling and object literals, visible template nesting, and separated CSS rules. An attractive page or formatter pass does not establish source readability. Exclude generated/minified assets, preserve behavior and scope, and keep owner readability unresolved until the owner reviews the concrete code. Do not turn a visual-only website audit into an unsolicited source refactor.

## Return a decision, with limits

Lead with readiness and the issue most likely to change buyer action. Order material findings by consequence. Give each a location/state, observation, buyer impact, supporting evidence and practical correction. Group systemic issues and link detailed proof. A fake primary conversion or unsupported central claim remains a failure regardless of unrelated passes.

Repair reversible defects only when implementation is in scope; review-only work does not edit the site. Recheck affected views and downstream journeys after repairs. Record concise findings in existing project records and stop at the requested outcome.

If another capability would resolve a named gap, recommend it with evidence: positioning (`website-discover`), design (`website-create`) or authorized launch (`website-deliver`). The agent decides; this skill invokes none and starts no mandatory workflow.
